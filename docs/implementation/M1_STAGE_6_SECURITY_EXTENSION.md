# Phase 1 M1 — Stage 6 successor extension

**Baseline:** Stage 5 GO commit `8dd62157d14e88400a9df1e97452a3807f3ed50e`, tag `phase-1-stage-5-go`; its Phase 0 manifest and Stage 5 security-extension baseline remain immutable. The accepted Stage 5 successor baseline has 38 protected files and SHA-256 aggregate `decc422c49ab17d44e700331b95ac3fdf0bee8d6058b244682ecdc6ab8940255` (baseline-file SHA-256 `ff41985b197738faa9585af2b4686612d420a9c118801a801c8d38087f1d29b6`). The exact Stage 5 source has been reverified in a detached worktree at the GO commit.

**Intentional successor delta:** Stage 6 adds two default-deny staff capabilities (`trip.preview`, `trip.publish`) and advances the permission registry to version 4; adds the strict customer-facing `PortalTripSnapshotV1` contract; adds a narrow publication source and shared deterministic projection; adds read-only staff Preview and version history; adds serializable Publish with revision/hash conflict detection, durable idempotency, bounded retry, atomic Audit/outbox/event records, immutable snapshot/version rows and an atomic active pointer; adds forward-only migration `0011_stage6_trip_publication.cjs`, qualification/tests and the Stage 6 CI successor wrapper. It also narrows the browser-bundle sensitive-data scanner to recognize only React DOM's exact public `accesskey` → `accessKey` property-map alias; regression tests continue rejecting arbitrary suspicious access-key material.

The extension does not change or relabel the Stage 5 baseline, and it does not grant `portal.access`, change the Portal role, publish mutable workspace state, expose the Staff history API to Portal, or implement Portal grants/access/consumption. Portal application behavior and Stage 7 remain excluded. Internal-only fields are structurally absent from the publication-safe source and strict snapshot. Preview and Publish use the same pure assembler.
